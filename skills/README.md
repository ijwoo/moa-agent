# 기능(스킬) 파일 기준

에이전트가 **할 수 있는 일** 하나가 이 폴더의 md 파일 하나다. 앱의 "할 수 있는 일" 탭은 이 파일들로 카드를 그리고,
에이전트 모델은 그 일을 할 때 **그 파일의 `## 모델 지시`만** 읽는다(모든 일이 읽는 공용 지시문에 줄을 더하지 않는다 — D46·D48의 교훈).

기능은 되는 것이 확인된 뒤에 하나씩 추가한다. 파일을 넣으면 서버를 다시 띄울 때 읽힌다.

## 파일 형식
```
---
id: mail_briefing              # 영문 소문자·숫자·밑줄. 파일 이름과 같다
title: 오늘 온 메일 브리핑        # 카드 제목
description: …                  # 카드 설명 한두 문장(사용자가 읽는 글)
prompt: 오늘 온 메일 요약해줘      # "부탁하기"를 누르면 대화창에 대신 보내는 말
category: 메일                   # 카드 묶음 이름
requires: [mail_account]         # 준비 조건(없으면 []). 아래 표
status: ready                    # ready(확인됨) | beta(일부만 확인) | planned(카드로 내보내지 않는다)
order: 10                        # 카드 순서(작을수록 앞)
---
## 무엇을 하나            ← 사람이 읽는 설명
## 모델 지시              ← 이 일을 할 때 모델에게 주는 지시. 이 절의 글만 모델에 들어간다
## 하지 않는 것           ← 범위 밖
## 확인된 것              ← 측정·시험 결과(날짜와 숫자)
```

## 준비 조건(`requires`)
| 값 | 뜻 | 안 되어 있을 때 카드가 권하는 말 |
|---|---|---|
| `mail_account` | 메일 계정이 연결돼 있다(IMAP·SMTP 로그인 확인됨) | "네이버 메일 연결해줘" |
| `site:naver` | 네이버에 사용자가 직접 로그인해 두었다 | "네이버 로그인해줘" |

## 원칙
- 로그인·인증은 사람이 한다(D53). 기능 파일은 로그인을 대신하는 절차를 적지 않는다.
- 바꾸는 일(보내기·지우기·설정 변경)은 승인 단계를 적는다.
- `## 확인된 것`에는 실제로 잰 것만 적는다. 재지 않은 것은 "확인 못 함"이라고 적는다.

## 기능을 늘릴 때의 기준 (사용자 지시 2026-11-14: "하나 늘릴 때마다 파이프라인을 단단하게")
새 기능(사이트·도구·행동)은 아래를 차례로 채운 뒤 다음 기능으로 간다. 못 채운 칸은 비워 두지 않고 "확인 못 함"으로 적어 보고한다.

1. **먼저 잰다.** 실제로 되는지(열리는지·막히는지·걸리는 시간)를 만들기 전에 잰다. 실제 사이트는 요청을 적게 — 첫 응답이 제한·차단이면 다른 입구를 두드리지 않고 거기서 멈춘다.
2. **값은 코드가 읽는다.** 이름·금액·날짜·상태는 화면 구조에서 코드가 뽑거나 받은 값 그대로 쓴다. 읽지 못한 것은 "읽지 못했다"가 답이다(모델이 채우지 않는다).
3. **실패 경로를 다 정한다.** 로그인 없음·풀림, 사이트가 막음, 시간 초과, 모델을 못 부름, 값이 비어 옴 — 각각 사용자에게 보이는 말과 작업 결과(outcome·reason), 알림 종류를 정하고 시험한다.
4. **바꾸는 일은 승인 뒤에만.** 승인한 내용과 실행 직전의 내용이 같을 때만 실행한다. 동의·수신·가입이 딸린 동작은 따로 승인받는다. 되돌릴 수 없는 마지막 동작(결제 등)은 사용자가 직접 한다.
5. **개인 내용의 경계를 긋는다.** Claude로 가는 것 / 가지 않는 것을 적고(`docs/API.md`), 가지 않는다는 것을 시험으로 고정한다. 기록에는 종류·시간·상태만 남긴다.
6. **고르는 판단을 잰다.** 평가 묶음에 "해야 할 말"과 "하지 말아야 할 말"을 함께 넣는다. 꺼져 있는 행동은 지시문뿐 아니라 고를 수 있는 값 목록에서도 뺀다.
7. **꺼져 있으면 예전 그대로.** features 이름과 스위치를 두고, 앱이 표시를 보내지 않거나 설정이 꺼져 있으면 동작이 달라지지 않게 한다. 되돌리는 방법을 `.env.example`에 적는다.
8. **앱과 형식을 먼저 맞춘다.** 필드 이름과 동작을 앱 세션에 알린 뒤 만든다. 모르는 값은 버리고 오류를 내지 않는다.
9. **세 겹으로 확인하고 나눠 적는다.** 단위 테스트 / 실제 서버(가상 값) / 실기기. 기능 파일의 상태는 planned(만들었지만 내보내지 않음) → beta(일부만 확인) → ready(실기기에서 확인).
10. **기록한다.** 결정(`docs/DECISIONS.md`), 측정(`docs/EVALUATION.md`), 회고(`docs/devlog/`), 기능 파일의 "확인된 것".
