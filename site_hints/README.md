# 사이트 요령 파일 기준 (D76)

엔진은 화면을 보고 스스로 찾아간다. 이 폴더에는 **자주 쓰는 사이트에서 겪은 것만** 얇게 적는다 — 사이트 하나가 md 파일 하나.
그 사이트에서 일할 때만 운전 모델에 붙는다. 파일이 없는 사이트는 요령 없이 자율로 한다(그것이 기본이다).

## 적는 것 / 적지 않는 것
- 적는 것: ① 어디서 시작하면 되는가 ② 겪었던 함정(먹통인 주소, 이름표 없는 칸, 새 창으로 뜨는 것, 막히는 곳) ③ 승인이 걸리는 지점.
- 적지 않는 것: "1번을 누르고 2번에 입력한다" 같은 순서(화면이 바뀌면 깨진다), 화면에서 읽은 내용·개인 정보·계정·주소록, 추측.
  **실제로 겪은 것만**, 언제 봤는지와 함께 적는다. 확인하지 못한 것은 "확인 못 함"이라고 적거나 적지 않는다.

## 요령은 권한이 아니다
요령 파일은 모델에게 주는 **참고 글**이다. 무엇을 해도 되는지는 코드가 정한다:
- 승인(저장·삭제·Enter·확인 창), 금지(탈퇴·비밀번호 바꾸기), 허용 호스트는 요령 파일로 바꿀 수 없다.
- `urls`(바로 열 수 있는 주소)는 그 사이트의 **허용 호스트 안의 것만** 받아들인다. 밖의 주소는 버린다.
- 화면과 요령이 다르면 화면을 따른다(요령은 낡을 수 있다).

## 파일 형식
```
---
host: myapp.example.dev        # 파일 이름과 같다(.md 빼고). 하위 주소에도 쓴다: pay.naver.com의 일에는 pay.naver.com.md, 없으면 naver.com.md
names: [내 서비스, myapp]           # 사용자가 부르는 이름(공개 길에서 이 낱말이 든 부탁에 붙인다). 없으면 []
urls: []                         # 바로 열어도 되는 주소(그 사이트의 허용 호스트 안). 없으면 []
seen: 2026-11-15                 # 마지막으로 실제 화면에서 본 날
---
## 시작
## 함정
## 승인
```
본문은 1,500자까지(넘으면 불러오지 않는다 — 얇게 유지한다). 파일을 넣으면 다음 작업부터 읽힌다(서버를 다시 띄울 필요 없음).

## 누가 적나
지금은 사람(개발자)이 측정·실기기에서 본 것을 적는다. 에이전트가 스스로 적게 하는 것은 아직 하지 않는다 —
화면의 글에 속아 틀린 요령을 적으면 다음 작업들이 그대로 따른다.
